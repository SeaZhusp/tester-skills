## 2. 三条不可协商的口径

### 2.1 唯一上游
**Spec Model 是所有下游产物的唯一输入。** 任何子技能都不允许：
- 直接读需求文档后自己数用例条数；
- 自己维护一份"功能点清单"副本。

违者视为产出无效。

### 2.2 唯一计量单位
**售前"预估用例数"与交付"实际用例数"必须同量纲、同聚合规则。**

- 唯一合法的条数来源是 `scripts/count_cases.py` 对 Spec Model 的输出。
- 不存在"独立验证点 = 1 条用例"这种备选口径：一个测试点是被校验的维度，一条用例是可执行的场景，两者不是同一层级的量。

### 2.3 唯一真相文件
**每个内容只有一份原文。**
禁止编写"规则概要""速查版""精简版"并把它放在比原文更靠前的位置——摘要在规则漂移后会成为最大误导源。

## 3. 依赖方向（只允许单向）

```
01 需求解构规约 ──┐
02 粒度契约 ──────┼──► 03 Spec Model schema ──► 04 计数与换算 ──► 产物
05 优先级 ────────┤
06 测试类型 ──────┘
07 追溯 ──────────┘
```

- `01/02/05/06/07` 是**基础规则**，互不依赖。
- `03` 依赖 `01/02`（schema 里的字段由解构规约与粒度契约决定）。
- `04` 依赖 `03`（换算基于 Spec Model 的枚举结果）。
- **禁止反向依赖**：基础规则里不得引用产物或换算结果。

## 4. 子技能权威边界

| 子技能 | 它**拥有**的专精 | 它**不得触碰**的 |
| --- | --- | --- |
| `qa-spec-engine` | 文档解析策略、模块切分手法、功能点命名、复杂度**定级执行**（判据来自 `01`） | 粒度定义、计数口径、优先级语义 |
| `qa-case-engine` | 用例文本组织、步骤/预期写法、场景串联技巧、Excel 样式 | 粒度定义（只能遵守 `02`）、优先级语义（只能遵守 `05`） |
| `qa-estimate-engine` | 报告结构、三档区间呈现、周期/人员换算、报价方案组织 | 条数从哪来（必须来自 `count_cases.py`）、粒度定义 |
| `qa-audit-engine` | 查漏策略、覆盖分析视角、校准建议生成 | 自行修改口径或参数；它只**报告**偏差，不擅自改标准 |

## 5. 冲突处置

1. 子技能与 `references/` 冲突 → **以 `references/` 为准**，子技能内容作废。
2. `references/` 内部冲突 → **停止执行**，向用户报告冲突点与两种解释，由用户裁决后**只改一处**。
   同一参数在两处出现不同取值，是最危险的一类冲突：使用者会绕开配置文件手工取值，从此口径彻底失控。必须一次修净。
3. 用户临时指定与 `references/` 冲突 → 记录为「本次任务例外」，并在产出中显式标注，**不得回写进规则文件**。
