# 07 · 追溯链路规约（Traceability Rules）

> 目标：**任何一条用例都能反查到它为什么存在，任何一个需求点都能查到谁覆盖了它。**
> 追溯是"可核销"的前提——没有追溯，售前与交付的一致性就无法验证。

---

## 1. 四段追溯链路

```
用例 TestCase  ──point──►  测试点 TestPoint  ──feature_point_id──►  功能点 FeaturePoint
                                                                        │
                                                                     note 中的 REQ 编号
                                                                        ▼
                                                                    需求条目 Requirement
```

| 段 | 载体 | 方向 |
| --- | --- | --- |
| 用例 → 测试点 | 用例的 `point` 字段（TP 编号，逗号分隔） | 必填 |
| 测试点 → 功能点 | 测试点的 `feature_point_id` | 必填 |
| 功能点 → 需求 | 功能点的 `source_ref`（需求章节/REQ 编号） | 必填 |
| 用例 → 需求 | 用例的 `note` 字段（写需求编号/描述） | 必填 |

---

## 2. 字段规范

### 2.1 用例集的追溯字段

| 字段 | 约束 |
| --- | --- |
| `id` | `TC-<模块短码>-<序号>` |
| `module` | 必填，必须能在 Spec Model 的 `modules[].name` 中匹配 |
| `point` | **必填**，一个或多个 TP 编号，逗号分隔（如 `TP-LOGIN-01,TP-LOGIN-02`）。**必须全部能在 Spec Model 中解析**。 |
| `note` | **必填**，必须包含需求追溯（如 `对应需求 REQ-LOGIN-01（账号密码登录）`），可追加自动化标记等说明 |

### 2.2 禁止

- `point` 为空或填写不存在的编号；
- `note` 为空或写"无"；
- 用例的 `module` 在 Spec Model 中找不到对应模块（说明解构与生成脱节）。

---

## 3. 核销规则（`scripts/check_consistency.py` 自动执行）

| 编号 | 规则 | 违反后果 |
| --- | --- | --- |
| T1 | 每条用例的 `point` 全部可解析 | FAIL |
| T2 | **每个测试点至少被一条用例引用**（测试点覆盖率 = 100%） | FAIL |
| T3 | 每个功能点至少有 1 个测试点 | FAIL |
| T4 | 每个模块至少有 1 条用例 AT 或其需求引用 | WARN |
| T5 | 用例的 `module` 均能在 Spec Model 中匹配 | FAIL |
| T6 | 每条用例的 `note` 非空且含需求引用 | FAIL |
| T7 | 每个模块的**模块覆盖率** = 该模块被引用的测试点数 ÷ 该模块总测试点数 | 覆盖率 < 90% 时 FAIL |
| T8 | 售前预估条数 vs 实际交付条数的偏差 | 偏差 > 20% 且无说明则 FAIL |

---

## 4. 覆盖率度量

```
模块覆盖率       = 已被用例引用的测试点数 ÷ 该模块测试点总数
功能点覆盖率     = 已被引用的功能点数 ÷ Spec Model 功能点总数
需求覆盖率       = 已被追溯的需求条目数 ÷ 文档需求条目总数
全链路覆盖率     = 能从用例一路回溯到需求条目的用例数 ÷ 用例总数
```

**交付门禁**：模块覆盖率 ≥ 90%，全链路覆盖率 = 100%。

---

## 5. 双向核对表（评估报告必附）

评估报告与核销报告都必须附下表，作为"售前 = 交付"的证据：

| 模块 | 功能点数 | 测试点数 | 售前预估用例数 | 实际交付用例数 | 偏差 | 覆盖率 |
| --- | --- | --- | --- | --- | --- | --- |
| 3.1 画布编排 | 10 | 43 | 12 | 12 | 0% | 100% |
| … | | | | | | |
| **合计** | | | | | | |

偏差列 = `(实际 − 预估) ÷ 预估`。偏差 > 20% 的模块必须在报告下方逐条说明原因。

## 6. 自检清单

- [ ] 每条用例都有 `point`，且全部可解析？
- [ ] 每条用例的 `note` 都含需求追溯？
- [ ] 测试点覆盖率 = 100%？
- [ ] 全链路覆盖率 = 100%？
- [ ] 是否存在孤儿测试点（无任何用例引用）？
- [ ] 是否存在孤儿用例（`point` 为空）？
- [ ] 双向核对表已附，且偏差 > 20% 的模块已说明？
