# 06 · 测试类型体系（Test Type Taxonomy）

> **唯一权威。** 用例生成、统计、计价三方共用本表。
> 一条用例**必须且只能**归属一个 `test_type`（主类型）。多类型交叉时取**主导类型**，其余写入 `note`。

---

## 1. 类型定义

| 类型 | 定义 | 典型用例 |
| --- | --- | --- |
| **功能** | 验证业务功能按需求正常工作（正向主流程、状态流转、业务规则） | 新增用户成功、订单状态合法转移 |
| **异常** | 验证非法输入/非法操作/依赖失败时的错误处理 | 必填缺失、格式非法、重复提交、依赖服务不可用 |
| **边界** | 验证输入/数值/长度的临界值 | 用户名长度 3/20/21、最大上传大小 |
| **权限** | 验证角色可见性与越权控制 | 普通用户访问管理员页面被拒 |
| **兼容** | 验证多浏览器/多分辨率/多终端表现 | Chrome/Edge/Firefox 下画布渲染一致 |
| **安全** | 验证数据保护与攻防 | 密钥脱敏、导出限制、XSS/SQL 注入、限流 |
| **性能** | 验证响应时间/并发/吞吐 | 100 并发下报告列表响应 < 2s |
| **UI** | 验证界面呈现与交互一致性（**必须有业务语义才单独立条**） | 缺陷统计图表正确渲染 |
| **接口** | 验证接口契约（字段、状态码、幂等、错误码） | 接口必传字段缺失返回 400 |

> **UI 类型限制**：纯样式/文案类断言**不单独立用例**（见 `02-case-granularity-contract.md` 第 1.2 节），应作为所属功能用例的预期片段。

---

## 2. 与用例类别的映射

用例生成时，`test_type` 与测试点 `category` 的对应关系：

| 测试点 category | 默认 test_type |
| --- | --- |
| 正向 | 功能 |
| 边界 | 边界 |
| 异常 | 异常 |
| 状态 | 功能（非法转移则为异常） |
| 权限 | 权限 |

**一条用例承载多个测试点、且跨 category 时**：取**承载测试点中优先级最高的类型**作为主类型，或取承载测试点数量最多的类型。选择依据写入 `note`。

---

## 3. 与计价的关系

- 按测试类型计价的方案见 `assets/pricing-config.json`（性能/安全单价通常高于功能）。
- 统计时**以用例的 `test_type` 为准**，一条用例只计一次，避免重复计价。
- 报告必须给出「类型 × 条数 × 单价 = 小计」的明细表，合计数必须与用例总数一致（`check_consistency.py` 核验）。

---

## 4. 测试类型锁

任务开始时的「测试类型锁」决定：
1. 是否铺开该类型的测试点（如未勾选性能，则**不生成**性能测试点）；
2. 是否纳入计价；
3. 是否纳入周期估算。

**默认只做**：功能、异常、边界、权限。兼容/安全/性能/UI/接口需用户显式勾选（避免顺手扩范围，违反套装共享契约 #10）。
