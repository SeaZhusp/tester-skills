# 需求审计检查清单（Audit Checklist）

本文件为 `tinypace-requirement-auditor` 技能的细化检查清单，按六个审查维度组织。每条包含**检查项**、**判定方法**与**典型风险**。审查时按需加载，对照文档逐条排查，并将命中项转化为 SKILL.md 规定的缺陷报告。

---

## 维度一：逻辑一致性（Logic Consistency）

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 模块间规则冲突 | 抽取各模块的同一业务规则（如计费、权限、状态），比对是否一致 | 同一用户在 A 模块可操作、B 模块被禁止，导致实现歧义 |
| 流程图与文字描述不符 | 将流程图分支与正文步骤逐条对齐 | 流程图画了分支，正文未提及，或反之；研发按其一实现即错 |
| 前后数值/范围矛盾 | 收集文档中所有阈值、数量、时间窗口，交叉核对 | "单笔上限 5 万"与"单日上限 1 万"并存，逻辑不自洽 |
| 角色与权限矩阵冲突 | 列出角色 × 操作矩阵，检查是否有越权或真空 | 某角色既能发起又能审批，违反职责分离 |
| 状态定义重叠/遗漏 | 枚举所有业务状态，检查是否互斥且完备 | 两个状态含义重叠，或存在"无状态"的中间态未被定义 |
| 术语口径统一 | 检索同一概念的不同叫法（如"订单/单据"） | 同一实体多名称导致研发建表/接口歧义 |

---

## 维度二：完整性与遗漏（Completeness & Gaps）

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 边界条件 | 对每个输入/输出追问：最小值、最大值、空值、超长、负数、0、特殊字符 | 未定义空列表/空结果展示，线上出现空白页或崩溃 |
| 异常与兜底 | 追问每个外部调用失败、超时、降级时的行为 | 第三方接口超时无兜底，界面永久 loading |
| 空状态 / 零数据态 | 检查列表、图表、表单在无数据时的呈现 | 新用户首屏白屏或报错 |
| 权限校验缺失 | 对每个写操作追问：未登录、越权、Token 失效时如何响应 | 越权访问导致数据泄露（安全类阻断） |
| 状态机逆向流程 | 对每个"正向"状态变更追问：能否撤销/回退/驳回 | 已支付订单无法取消，用户投诉且无流程 |
| 并发与重试 | 追问重复提交、双端同时操作、消息重放 | 重复点击导致重复扣款（竞态条件） |
| 逆向/取消/删除 | 检查创建对应是否有改、删、撤回入口与规则 | 数据只能进不能出，合规风险 |
| 失败重试与幂等 | 检查写接口是否声明幂等键 | 网络重试产生重复业务单据 |
| 过期/失效处理 | 检查临时凭证、优惠券、会话到期时的行为 | 过期资源仍可访问 |

## 维度三：清晰度与可测性（Clarity & Testability）

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 模糊形容词 | 检索"快/友好/适当/尽量/视情况/较/大概"并追问量化标准 | 无法写断言，"响应要快"不知目标是多少 ms |
| 未定义参数 | 对每个条件中的变量追问其来源、类型、取值范围 | "超过阈值告警"——阈值未给，无法测试 |
| 条件分支不完整 | 用决策表枚举所有条件组合，看是否覆盖 | if/else 有遗漏分支，分支未定义行为 |
| 可转化为用例 | 每条需求能否写出"前置-操作-期望"三步用例 | 抽象需求无法直接测，测试只能凭感觉 |
| 多义表述 | 检查"等/相关/其他/必要时"等开放词 | 范围无限扩张或理解不一致 |
| 验收标准缺失 | 检查是否每条需求都有可判定完成的验收口径 | 需求完成与否无共识，扯皮 |

---

## 维度四：技术与业务可行性（Feasibility）

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 竞态条件 | 多用户/多进程同时操作共享资源时是否有锁或事务 | 库存超卖、余额错乱 |
| 第三方依赖约束 | 列出所有外部接口，追问限流、鉴权、SLA、字段约束 | 依赖方限流未考虑，大促被打垮 |
| 兼容性破坏 | 改动是否影响存量数据/旧版本客户端/历史接口 | 改字段导致老版本崩溃或老数据脏读 |
| 性能与容量 | 追问预估量级、响应时间、是否分页/缓存 | 全表扫描在大体量下超时 |
| 数据安全与合规 | 检查敏感字段（手机号/身份证/密码）的存储、传输、展示脱敏 | 合规违规、隐私泄露 |
| 幂等与一致性 | 分布式下最终一致性如何保障、是否有对账 | 数据不一致且无兜底对账 |
| 可观测性 | 是否定义关键埋点、日志、监控告警 | 线上异常无法定位 |
| 降级与开关 | 是否定义功能开关、灰度、回滚方案 | 出问题无法快速止损 |

---

## 维度五：合规与安全基线（Compliance & Security Baseline）

> 本维度覆盖"上线前必须满足、否则被监管或安全卡停"的硬性约束，多为 阻断 项。

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 法律法规 / 隐私 | 检查是否涉及个人信息/敏感数据，是否说明告知同意、最小化采集、主体权利（查询/删除） | 违反个保法/GDPR，监管处罚、下架 |
| 等保 / 密评 | 是否定义系统等级保护要求、加密与审计基线、密评材料 | 上线前等保不通过被叫停 |
| 无障碍 / 适老化 | 是否考虑读屏兼容、字体缩放、对比度、大字号模式 | 合规不达标 + 体验双失 |
| 认证与授权 | 是否定义认证方式（多因子？）、权限模型（RBAC？）、最小权限原则 | 越权/未授权访问 |
| 数据加密 | 传输是否强制 HTTPS、存储是否强制哈希/加密、密钥如何管理 | 数据泄露、中间人窃听 |
| 安全审计 | 关键操作（登录/改密/授权/资金）是否留痕、是否可告警 | 安全事件不可追溯 |
| 注入与防护 | 是否要求参数化查询（防 SQL 注入）、登录防 CSRF、防 XSS | 注入/越权类高危漏洞 |
| 第三方合规 | 引入的 SDK/接口/开源组件是否有合规授权与隐私声明 | 违规采集、连带责任 |

## 维度六：价值 / 范围 / 上线闭环（Value, Scope & Rollout）

> 本维度确保需求"做对的事、边界清楚、能安全上线"，多为 严重/细节，但缺失范围与回滚可直接升级为 阻断。

| 检查项 | 判定方法 | 典型风险 |
| :--- | :--- | :--- |
| 业务必要性 / 价值 | 每条需求是否对应明确问题与收益，有无过度设计/伪需求 | 为错误的事做高质量实现，资源浪费 |
| 范围边界 In/Out | 是否显式列出本期不含项（如注册/忘记密码/第三方登录） | 范围蔓延、漏做扯皮 |
| 优先级 / MVP | 是否区分必须/可选、切分合理，关键项是否排期靠后 | 关键路径阻塞、延期 |
| 依赖与时序 | 需求间、跨团队依赖是否识别，是否存在"A 等 B" | 依赖未就绪导致联调阻塞 |
| 唯一 ID / 可追溯 | 需求是否有编号，可追溯到设计/用例/上线 | 变更影响分析失效 |
| 灰度 / 回滚 / 开关 | 是否定义特性开关、灰度策略、回滚方案 | 出问题无法快速止损 |
| 上线后监控 | 是否定义核心指标（成功率/耗时/错误率）监控与验收门槛 | 上线即黑盒，故障发现滞后 |
| 数据留存与销毁 | 是否定义采集数据的留存周期与销毁规则 | 超期留存违规、存储成本虚高 |

## 快速命中信号（一见即标）

以下表述出现即应标记为缺陷，无需犹豫：

- "响应要快 / 尽快 / 性能良好"（无量化 → 严重）
- "界面友好 / 体验好 / 适当"（无标准 → 严重）
- "视情况而定 / 后续版本支持 / 暂不实现"（甩锅/留坑 → 严重 或 细节）
- "大概 / 可能 / 应该"（不确定 → 细节）
- "等等 / 相关 / 其他"（范围不清 → 严重）
- "由研发决定 / 前端自己处理"（职责推诿，需求未定义 → 严重）
- "符合相关法规 / 满足安全要求"（空话无具体基线 → 阻断/严重，需落到具体条款）
